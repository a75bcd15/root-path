Протокол SIP (Session Initiation Protocol)

Современный стандарт протокола — SIP 2.0. Основной документ, который его описывает и регламентирует — RFC 3261. SIP работает на прикладном уровне модели OSI. Для доставки SIP-сообщений чаще всего используется протокол UDP (порт 5060 или 60000), но также могут применяться TCP (порт 5060) и зашифрованный TLS (порт 5061).

Структура

SIP — это текстовый протокол (ASCII), очень похожий по своей структуре и логике на HTTP. Любое SIP-сообщение состоит из трех основных частей:

[ Стартовая строка (Start-line) ] -> Описание запроса или статус ответа [ Заголовки (SIP Headers) ] -> Метаданные (кто, кому, как передавать) [ Пустая строка (\r\n) ] -> Разделитель [ Тело сообщения (Message Body) ] -> Обычно описание медиапотока через SDP

Заголовки в SIP-пакете:

  • Via: — содержит путь (IP и порт), пройденный запросом. Используется для маршрутизации ответов назад.
  • From: — логический инициатор запроса (кто звонит). Содержит SIP URI и уникальный тег tag.
  • To: — логический получатель запроса (кому звонят). Содержит SIP URI.
  • Call-ID: — уникальный глобальный идентификатор конкретного звонка/сессии. Связывает все запросы и ответы в рамках одного диалога.
  • CSeq: (Command Sequence) — порядковый номер запроса и имя метода (например, 1 INVITE). Помогает упорядочить сообщения.
  • Max-Forwards: — счетчик (обычно 70), ограничивающий количество транзитных узлов (прокси), которые может пройти пакет, для защиты от зацикливания.
  • Contact: — прямой URI для связи с конкретным устройством. Именно на этот адрес отправляются последующие запросы в рамках диалога (в обход промежуточных прокси).
  • Content-Type: — тип данных в теле сообщения (чаще всего application/sdp).
  • Content-Length: — длина тела сообщения в байтах.

Все сообщения SIP делятся на два типа: Запросы (Requests) и Ответы (Responses).

Запросы (Requests)

Основные запросы (Методы):

  • REGISTER — устройство передает серверу (Registrar) свой текущий IP-адрес для регистрации в сети.
  • INVITE — инициация сессии (приглашение к разговору, звонок).
  • ACK — подтверждение от вызывающей стороны, что окончательный ответ на INVITE получен.
  • BYE — завершение разговора (повесили трубку на одной из сторон).
  • CANCEL — отмена еще не установленного вызова (вызывающий нажал «отбой» до того, как ему ответили).
  • OPTIONS — запрос поддерживаемых функций и проверка доступности сервера («пинг» на уровне SIP).

Ответы (Responses)

Ответы состоят из 3-значного цифрового кода и текстового пояснения:

  • 1xx (Информационные) — запрос обрабатывается, звонок идет. (Пример: 100 Trying — пытаюсь связаться, 180 Ringing — идет гудок).
  • 2xx (Успех) — запрос успешно выполнен. (Пример: 200 OK — трубку сняли или регистрация успешна).
  • 3xx (Перенаправление) — требуется перенаправить вызов на другой URI.
  • 4xx (Ошибка клиента) — запрос содержит ошибку или не может быть выполнен. (Пример: 401 Unauthorized — нужна авторизация, 404 Not Found — номер не найден).
  • 5xx (Ошибка сервера) — сервер не может обработать корректный запрос. (Пример: 503 Service Unavailable).
  • 6xx (Глобальная ошибка) — вызов не может быть выполнен ни на одном сервере. (Пример: 603 Decline — абонент отклонил вызов).

Схема 1: Регистрация на сервере

Процесс авторизации софтфона или телефона на АТС:

    Абонент (Телефон)                     Сервер (АТС)

           |                                   |
           |------- 1. REGISTER -------------->| (Попытка регистрации без пароля)
           |<------ 2. 401 Unauthorized -------| (Сервер требует авторизацию и шлет nonce)
           |                                   |
           |------- 3. REGISTER -------------->| (Повторный запрос с хэшем пароля)
           |<------ 4. 200 OK -----------------| (Успешная регистрация)

Схема 2: Успешный звонок

Классическая схема установления соединения и завершения разговора.

    Вызывающий (А)                        Вызываемый (Б)

           |                                   |
           |------- 1. INVITE ---------------->| (Хочу позвонить, внутри SDP)
           |<------ 2. 100 Trying -------------| (Запрос обрабатывается)
           |<------ 3. 180 Ringing ------------| (У абонента Б идет гудок)
           |                                   |
           |<------ 4. 200 OK -----------------| (Абонент Б снял трубку, внутри SDP)
           |------- 5. ACK ------------------->| (Подтверждение соединения)
           |                                   |
           | <======= МЕДИАПОТОК RTP ========> | (Идет разговор абонентов)
           |                                   |
           |                                   | (Абонент Б вешает трубку)
           |<------ 6. BYE --------------------| (Завершение сессии)
           |------- 7. 200 OK ---------------->| (Подтверждение закрытия)

Схема 3: Отмена вызова до ответа

Ситуация, когда абонент А передумал звонить, пока у абонента Б играла мелодия вызова.

    Вызывающий (А)                        Вызываемый (Б)

           |                                   |
           |------- 1. INVITE ---------------->| (Звонок)
           |<------ 2. 180 Ringing ------------| (Идет гудок)
           |                                   |
           |------- 3. CANCEL ---------------->| (Абонент А нажал отмену)
           |<------ 4. 200 OK (на CANCEL) -----| (Сервер подтвердил отмену запроса)
           |<------ 5. 487 Request Terminated -| (INVITE официально закрыт по отмене)
           |------- 6. ACK (на 487) ---------->| (Подтверждение закрытия INVITE)
